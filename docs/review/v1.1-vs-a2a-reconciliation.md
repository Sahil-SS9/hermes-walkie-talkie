## 1. Executive Summary

Walkie Talkie V1.1 (7,466 lines production + 13,891 lines test) and Hermes A2A (3,219 lines) solve **different transport problems** with significant feature-level overlap. The overlap is real but shallow — the same *concept* appears in both systems, but the *implementation contract* differs fundamentally:

| Dimension | Walkie Talkie V1.1 | Hermes A2A |
|-----------|-------------------|------------|
| **Transport** | AF_UNIX local sockets, same machine, same OS user | HTTP JSON-RPC over network, any machine |
| **Identity** | Stable `agent_id` per profile + session-scoped `peer_id` | Per-peer bearer tokens, `contextId` for conversation threading |
| **Discovery** | Registry files + DISCOVER/ALIVE probe over Unix socket | Agent Card at `/.well-known/agent-card.json`, HTTP GET |
| **Messages** | Length-prefixed JSON frames, 32 KiB ceiling | JSON-RPC `message/send`, unbounded Parts, v1.0 SCREAMING_SNAKE_CASE |
| **Fan-out** | Group Store + BroadcastEngine with deterministic child IDs | `a2a_orchestrate` with `all`/`first`/`best` modes |
| **Task lifecycle** | `created → queued → accepted → in_progress → completed\|failed\|refused\|cancelled\|expired` | `SUBMITTED → WORKING → COMPLETED\|FAILED\|CANCELED\|REJECTED` (+ INPUT_REQUIRED, AUTH_REQUIRED) |
| **Delivery** | Exact-session `surface:session_id` targeting, queue-safe at busy boundary | Live-session injection via `ctx.inject_message`, context-scoped FIFO |
| **Receipts** | Transport-level: queued/held/refused/unreachable/expired/invalid/rate_limited/over_capacity | A2A task states (not separate receipts) |
| **Security** | Same-UID check (SO_PEERCRED), owner-only files, symlink refusal | Bearer tokens, per-peer identity, localhost-default bind, injection filters, outbound redaction, SSRF guards, audit log |
| **Persistence** | SQLite WAL, idempotent dedup, bounded retention | In-memory task store (last 500), conversation JSONL files outside compaction |
| **Protocol** | `agent-peer/1` + `agent-peer/2` (negotiated per-connection) | A2A Protocol v1.0 (JSON-RPC 2.0) |

**Bottom line:** V1.1's unique value is **same-machine exact-session mailbox delivery with queue-safe busy handling**. A2A's unique value is **cross-machine remote agent calling with standard protocol**. The overlap is in *concepts* (identity, discovery, task state, fan-out, history), not in *implementation*. Removing either would lose irreplaceable capability.

## 2. Capability-by-Capability Evidence Matrix

Each capability is classified as **RETAIN** (unique local value), **ADAPT** (bridge to A2A), **REUSE** (delegate to upstream A2A), or **REMOVE** (proven duplication).

### 2.1 Identity

| Aspect | V1.1 Source | A2A Source | Classification | Rationale |
|--------|-------------|------------|----------------|-----------|
| Stable per-profile UUID (`agent_id`) | `agent_identity.py:load_or_create_agent_id` — persisted owner-only under `HERMES_HOME/agent-peer/agent_id`, never inferred from alias/path | Not present — A2A identity is per-peer token, no stable UUID across sessions | **RETAIN** | V1.1's stable agent_id is the foundation for group membership, broadcast dedup, and request idempotency. A2A has no equivalent. Removing it would break groups/broadcasts. |
| Session-scoped `peer_id` | `identity.py:generate_peer_id` — UUID per live registration, rotates on session reset | Not present — A2A uses `contextId` for conversation threading | **RETAIN** | peer_id is the transport handle for Unix socket routing; A2A's contextId is conversation-scoped, not transport-scoped. Different purpose. |
| Host metadata (cwd, hostname, pid, git branch) | `identity.py:host_metadata` | Not present — A2A agent cards have `provider`, `url`, `capabilities` | **RETAIN** | Local machine context is unique to same-machine discovery. |

### 2.2 Discovery

| Aspect | V1.1 Source | A2A Source | Classification | Rationale |
|--------|-------------|------------|----------------|-----------|
| Registry files + DISCOVER/ALIVE probe | `discovery.py` — reads `XDG_RUNTIME_DIR/agent-peer/*.json`, validates filename/peer-ID/same-UID, probes via socket | `a2a_discover` — fetches `/.well-known/agent-card.json` over HTTP | **RETAIN** | Same-machine discovery via shared filesystem + socket probe is orthogonal to network Agent Card fetch. Both are needed for different scopes. |
| `resolve_peer(target)` — fail-closed resolution | `discovery.py:resolve_peer` — exact peer_id, exact session_id, `name~short`, bare name with collision handling | Not present — A2A resolves by configured peer name or URL | **RETAIN** | Local peer resolution with collision disambiguation has no A2A equivalent. |
| `repair_stale()` — race-safe cleanup | `discovery.py:repair_stale` — re-reads inodes before mutation, refuses on ambiguity | Not present | **RETAIN** | Stale-socket cleanup is a local-filesystem concern that doesn't exist in HTTP A2A. |

### 2.3 Agent Cards / Capabilities

| Aspect | V1.1 Source | A2A Source | Classification | Rationale |

V1/V2 negotiation is for local binary framing; A2A version negotiation is for HTTP JSON-RPC. |
| Capability flags (`capability_flag`) | `capabilities.py:capability_flag` — boolean flags per peer | A2A `capabilities` array in agent card | **ADAPT** | Could be bridged: local capability flags could be advertised in A2A Agent Cards when a peer is also reachable remotely. |

### 2.4 Groups

| Aspect | V1.1 Source | A2A Source | Classification | Rationale |
|--------|-------------|------------|----------------|-----------|

Removing them would lose group-based broadcast entirely. |
| Group membership by stable `agent_id` | `groups.py` — `agent_id` (required) + optional `peer_id` pin | Not present | **RETAIN** | Depends on stable agent_id from 2.1. |

### 2.5 Broadcasts / Fan-out

| Aspect | V1.1 Source | A2A Source | Classification | Rationale |
|--------|-------------|------------|----------------|-----------|
| Bounded broadcast engine | `broadcast.py:BroadcastEngine` — parent-first persist, deterministic child IDs, atomic `created→in_flight`, bounded concurrency | `a2a_orchestrate` — `all`/`first`/`best` modes, ThreadPoolExecutor fan-out | **RETAIN** | Broadcast engine provides group-aware, deterministic, idempotent local fan-out with per-member receipts. A2A orchestrate is fire-and-forget over HTTP. Different delivery guarantees. |
| Deterministic child IDs | `broadcast.py:deterministic_child_id` — UUID5 from `(broadcast_id, agent_id, peer_id)` | Not present | **RETAIN** | Idempotent retry guarantee depends on deterministic IDs. |

### 2.6 Request/Task Lifecycle

| Aspect | V1.1 Source | A2A Source | Classification | Rationale |
|--------|-------------|------------|----------------|-----------|

1. **Merge `metrics.py` + `health.py` + `events.py`** (231 LOC combined). All three serve observability. A single `observability.py` module with three concerns (counters, snapshots, broker) would reduce the shallow-module smell without losing any depth. **SAFE**.

3. **No module is a pass-through wrapper.** Every module earns its interface. The architecture is already deep.

### 4.1 Uncommitted Diff Analysis

The uncommitted diff adds OSError handling to `posix.py` and `transport.py`:

```python
# posix.py — wraps sendall/recv OSError as UnreachableError
try:
    sock.sendall(_frame(frame))
except OSError as exc:
    raise UnreachableError(f"cannot send to {endpoint.address}: {exc}") from exc
```

**Assessment:** This is a correctness fix. The existing code would raise bare `OSError` on broken connections instead of the documented `UnreachableError`. **SAFE** to apply.

## 5. Recommendations

### RETAIN (keep as-is, V1.1 unique value)

These capabilities have no A2A equivalent and must remain:

1. **Stable agent identity** (`agent_identity.py`) — Foundation for groups, broadcasts, requests
2. **Same-machine discovery** (`discovery.py`) — Registry + probe, no HTTP equivalent
3. **Groups** (`groups.py`) — No A2A concept of persistent groups
4. **Broadcast engine** (`broadcast.py`) — Deterministic, idempotent local fan-out
5. **Structured requests** (`requests.py`, `workflows.py`) — Local idempotency, correlation, event log
6. **Local transport** (`transport.py`, `runtime.py`, `backends/`) — AF_UNIX + Windows named pipes
7. **Queue-safe delivery** (`sessions.py`, `delivery.py`) — `surface:session_id` targeting, busy-boundary FIFO
8. **Policy engine** (`policy.py`) — Per-pair rate limits, accept/hold/refuse
9. **Owner-only security** (`paths.py`, `posix.py`) — Same-UID, file permissions, symlink refusal
10. **Protocol negotiation** (`capabilities.py`, `protocol_v2.py`) — V1/V2 wire versioning

### ADAPT (bridge V1.1 to A2A)

These are where V1.1 can expose its local capabilities through A2A:

1. **Agent Card generation** — V1.1's `DiscoveryService` could populate A2A `agent-card.json` with local peer capabilities. This lets remote A2A callers discover what a local peer can do.
2. **Request → Task mapping** — V1.1's `RequestStore` could bridge to A2A's task states: `queued → TASK_STATE_SUBMITTED`, `accepted → TASK_STATE_WORKING`, etc. A remote A2A caller could query a local peer's request status.
3. **Inert boundary bridging** — A2A inbound text already gets injection-filtered; wrapping it in `<peer_request>` markers would give V1.1 the same security boundary for remote requests.
4. **Health/metrics → A2A** — V1.1's `health.py` snapshots could be exposed via A2A Agent Card `capabilities`.

### REUSE (delegate to upstream A2A)

These are where V1.1 should not build its own version:

1. **Remote agent calling** — V1.1 should not implement HTTP JSON-RPC client calls. Use `a2a_call` / `a2a_orchestrate`.
2. **Remote Agent Card discovery** — V1.1 should not implement HTTP `/.well-known/agent-card.json`. Use `a2a_discover`.
3. **Cross-machine conversation persistence** — V1.1's SQLite store is for local messages. Remote conversations should use A2A's `a2a_conversations/` JSONL.
4. **Bearer token auth** — V1.1's same-UID auth is correct for local. Remote auth should use A2A's per-peer tokens.

### REMOVE (proven duplication)

**None.** No V1.1 capability is a proven duplicate of A2A. The concepts overlap (identity, discovery, task state, fan-out) but the implementations serve different transport domains. Removing any V1.1 module would lose unique same-machine value.

## 6. Proposed Architecture: Keep Local Value, Ride A2A for Remote

```
┌─────────────────────────────────────────────────────────────┐
│                    Hermes Agent Process                      │
│                                                              │
│  ┌──────────────────────┐    ┌───────────────────────────┐ │
│  │  hermes_peer          │    │  A2A plugin               │ │
│  │  (local adapter)      │    │  (remote adapter)          │ │
│  │                      │    │                            │ │
│  │  sessions.py ────────┼───►│  (bridge: request→task)   │ │
│  │  delivery.py          │    │  (bridge: agent_card←disco)│ │
│  │  tools.py             │    │  tools.py (outbound)       │ │
│  │  commands.py          │    │  adapter.py (inbound)      │ │
│  └──────────┬───────────┘    └───────────────────────────┘ │
│             │                                                │
│  ┌──────────▼───────────┐                                   │
│  │  agent_peer (core)    │                                   │
│  │                      │                                   │
│  │  identity ──── agent_identity (stable UUID)             │
│  │  discovery ─── registry + DISCOVER/ALIVE                │
│  │  groups ────── GroupStore (SQLite)                      │
│  │  broadcast ─── BroadcastEngine (deterministic)           │
│  │  requests ──── RequestStore + workflows                  │
│  │  transport ─── PeerClient (AF_UNIX / Win pipe)          │
│  │  runtime ───── PeerRuntimeManager (selector loop)       │
│  │  policy ────── accept/hold/refuse + rate limits         │
│  │  paths ─────── owner-only runtime roots                  │
│  │  codec ─────── framed JSON (V1 + V2)                    │
│  │  store ─────── MessageStore (SQLite WAL)                │
│  └──────────────────────┘                                   │
└─────────────────────────────────────────────────────────────┘
```

**Bridge opportunities (ADAPT tier):**
- V1.1 discovery → A2A Agent Card (expose local capabilities to remote peers)
- V1.1 requests → A2A tasks (map local request state to A2A task state)
- V1.1 health → A2A capabilities (advertise local health in Agent Card)

**No module removals proposed.** The local transport layer is the irreplaceable value of V1.1.
